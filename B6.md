## FP32 GEMM and the copy-versus-CPU choice

`b6/fp32_nvrtc.cpp` JIT-compiles one expert matrix with CUDA 12.8 nvrtc, `--gpu-architecture=compute_60`. Shape K=2048, N=1408 (one of the three Qwen1.5-MoE routed matrices). The kernel is FP32 multiply-add. It is not DP4A and not int4 MMA. sm_60 has neither. Log: `b6/fp32-nvrtc.txt`.

Mapped `libnvrtc.so.12.8.93` and `libnvrtc-builtins.so.12.8.93`. nvrtc reported version 12.8. `libnvrtc.so.13` was not mapped. The B5 CubeCL GEMM was not switched to FP16.

| Measurement | Time | Bytes |
|---|---:|---:|
| Host to device, Q4_K packed | 0.306933 ms | 1622016 |
| Host to device, FP32 | 1.832188 ms | 11534336 |
| GPU FP32 GEMM | 0.248902 ms | |
| CPU FP32 GEMM, same loop | 4.219502 ms | |

One matrix, copy the Q4 bytes then run the FP32 GEMM: 0.306933 + 0.248902 = **0.556 ms**. CPU for that same matrix: **4.220 ms**. The choice for this shape is the Q4 copy plus the FP32 GEMM. Gate, up, and down are the same element count, so three matrices scale both sides by three and the choice stays the copy.

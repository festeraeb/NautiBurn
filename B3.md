## How each row is scored

Counts update only after the position is scored. Decode frequency reads the finished prefill histogram and does not see the decode token.

- Frequency. Online per-layer counts from earlier tokens in that phase. The public slice has one token, so the prior is empty (hit 0, 16 positions, 0 slabs).
- Previous-token copy. Same layer, the immediately previous token index. Decode copies a prefill row only when that row is the last prefill index at the layer. Layer 15's only prefill row is token index 0, not 13, so decode layer 15 is not scored (15 positions). The public slice has no earlier token (`n/a`).
- Cross-layer bigram. Joint `[layer, expert, next_expert]`, updated after the token. Predict layer L+1 from the experts just observed at layer L. The first token's joint is empty, so those positions score 0. Public joint starts empty (hit 0, 15 positions).
- Request-matrix cosine. Each B1 prefill token is a binary vector of length `16 * 64`. The decode query is the sum of those vectors. The nearest prefill profile is copied onto the decode token. Prefill is the query, so that column is `n/a`. The public slice is one token and its routing is the label, so this row does not score it. Reverse direction, decode profile against prefill, is 0.2873 and is not a sixth row.
- LRU next-layer. Inside one token, the prediction for layer L+1 is the expert set just observed at layer L. This is a score. No token is drafted and no extra forward runs.

## Handwritten PAMP router

`Track2-Cesarops-Hadfield-Radeon-hackathon-2026-07` `src/moe.rs` `route_hidden_state` takes a hidden state and a gate-weight matrix. Its scratch pad is 128 experts. The B1 trace has phase, layer, token index, token id, tensor name, and the eight expert ids. It has no hidden state and no gate weights, so that function cannot be called on the trace. Forge `predict_expert_plan` returns role names (`thinker_r1`, `coder_gemma`, and the like), not OLMoE expert ids. No hit rate.

## PAMP path that can emit expert ids

`route_hidden_state` already emits expert ids when it is given both inputs. OLMoE has 64 experts, which fits the 128-wide scratch. The call is a dot product of the layer hidden state with `gate_weights` shaped `[64, hidden]`, a softmax, then the top 8 indices. Those ids are what a later row would score against `expert_ids`.

The scrape has to grow two fields the current columns do not have: the gate input hidden state for that layer and token (the vector llama.cpp multiplies by `blk.{layer}.ffn_gate_inp.weight`), and that F32 gate matrix itself. Until both are in the trace, this path still cannot be scored. No hit rate.
